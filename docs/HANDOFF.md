## 1. Purpose

LivingLacquer collects the tools used to model and texture scanned lacquerware into one add-on. Each tool is a module under `addons/LivingLacquer/modules/`, switchable from the Infos panel (Debug on).

## 3. metashape notes

- Coordinates: the OBJ must be imported Forward = Y, Up = Z. The chunk transform (rotation, translation, scale) is applied to every camera.
- Camera model: sensor width fixed at 36 mm, `lens = f * 36 / max(w, h)`, `shift = (-cx, cy) / max(w, h)`. The undistorted photo keeps f / cx / cy, so it lines up with the pinhole camera.
- Undistortion: Brown model (k1-k4, p1, p2, b1, b2) remapped with numpy in 256-row strips, bilinear sampling, black outside the source.
- Photos that do not fit their own sensor (other aspect, rotated) are skipped by default; each lens is checked separately, so mixed-lens shoots keep all cameras.
- Camera objects keep `metashape_res` and `metashape_photo` custom properties.

## 6. Scan pipeline notes (0.2.0)

- **Panel:** LivingLacquer › Scan Pipeline. Each step is drawn by the module that owns it (`project/ui.py` STEPS). **Every wait is a job** (`project/jobs.py`, one at a time): progress bar + Cancel at the top of the panel and the same line in the status bar; Python steps are generators yielding (fraction, "what"), run in 0.1 s slices, "Show Log" writes the log into the text block "LivingLacquer Log". Engine logs also land in `zz.Scan\zz.COLMAP_OMVS\logs`.
- **Step 2:** `receiver.py` serves on 0.0.0.0, first free port from 8765, random token in the URL (403 without it), photos only (415), 300 MB cap, writes to `zz.Originals` through a temp file. QR code needs segno (Install button). Windows asks once to allow Blender through the firewall. iOS Shortcut: Get Contents of URL, POST, `http://<pc>:<port>/upload?t=<token>&name=<file>`, body = file. Convert & Sort starts 8 s after the last upload. The eye button watches the photo folders instead.
- **Step 3:** pillow / pillow-heif / rawpy / segno are pip-installed into Blender's user `scripts\modules`. Conversion runs in `worker.py` with Blender's Python (process pool). Rule: a JPG of the photo wins; HEIC / RAW / PNG without one are converted (EXIF rotation baked, EXIF + ICC kept, q95, 4:4:4); originals, IMG_E edits, videos and Drive duplicates go to `zz.Originals`; received JPGs move from `zz.Originals` up to `zz.Source_Photos`.
- **Step 4:** Agisoft = Open Metashape (photo folder on the clipboard), the guide with copy buttons, and a watcher that waits until CAM xml + model + texture exist and stop growing. The Batch Process job file from the plan is NOT written (its format still needs checking in Metashape Standard). Hybrid = Agisoft only aligns + exports cameras; the XML is copied with absolute photo paths as labels (InterfaceMetashape reads photos from the labels), then Densify / Mesh / Refine / Texture. Open Source = photos copied locally into one folder per photo size (one COLMAP camera per lens), feature_extractor (OPENCV) / exhaustive_matcher / mapper / largest model / model_orientation_aligner / image_undistorter / model_converter TXT -> `CAM_<Object>.xml` (pinhole) / InterfaceCOLMAP / OpenMVS. Work folder: `%LOCALAPPDATA%\LivingLacquer\work\<object>_<id>\<engine>` (depth maps ~36 MB per photo stay off Drive). Result + `engine_result.json` -> `zz.COLMAP_OMVS\result`, then published automatically.
- **Step 6:** Alembic from Metashape is Z-up but Blender's importer turns it as Y-up, so ABC starts at X -90 deg; Build tries X 0 / -90 / +90 / 180 and keeps the rotation where most mesh vertices project inside 9 sample photos (Teapot: -90, 86 %). Cameras that come with the ABC are deleted (XML wins). `OBJ_<Object>` goes to the `OBJECTS` collection and is replaced on every Build; materials `MAT_<Object>[_n]` are linked to the object. Cameras go to `CAMERAS` (cameras only) and are updated by name; scan cameras no longer in the XML are removed. These are the names MultiCamProject looks for (its roles.py). The mesh and every camera are parented to the `Transform` empty (alone in the `TRANSFORM` collection) with their XML-space matrix as local matrix, so moving / rotating / scaling `Transform` moves the whole scan and survives re-runs. Old `Geometry_<Object>` / `Cameras_<Object>` collections are removed once empty.
- **Step 7:** undistorts only missing photos, or all of a lens whose calibration fingerprint changed (stored per sensor in livinglacquer.json). Skipped when the published photos are already undistorted (COLMAP).
- **Step 8:** copies the newest `engine_result.json` result into `01.CAM_Photos` / `02.Geometry` with the standard names (only changed files), rewrites the OpenMVS .mtl, records `published` in the marker, makes the .blend paths relative. With Agisoft exports there is nothing to copy.
- **Local cache (⚙):** Pull mirrors the object folder into `<work folder>\cache\` with robocopy and marks it checked out on Drive; Push copies newer files back (marker merged by hand) and releases it. COLMAP's dense folder is never copied.
- **Not done from the plan:** manual path slots in ⚙ (auto-detect only), "Exclude ultra-wide from texturing", the Metashape Batch Process file, the A1 confirm dialog (loose matches are only reported), MulticamProject reading the marker.
- **Auto Level & Center (`scene/level.py`):** computed from the data, never a stored G / R / S: up = normal of the plane through the camera positions (SVD of the camera centers; sign from the cameras' own up vectors), rotation = the smallest one taking that normal to +Z (no extra turn about Z), translation = minus the center of the mesh's vertex bounding box after that rotation, scale kept. Writes only the `Transform` matrix and sets `Transform["ll_levelled"]`. Runs by itself on a Build while `Transform` is still fresh (identity, never levelled), then starts interactive scaling (`transform.resize` with `center_override` = world origin); the Auto Level & Center and Scale buttons redo either one. On the Teapot it tilts 31 deg, matching the user's hand-levelled 30.7 deg; up within 0.3 deg. Fails for captures that are not a ring around the object (e.g. one straight line of photos): then level by hand.
- **Size references (`scene/human.py`):** GPU overlay, toggle "Size refs" next to Build (`pipe_show_human`): 1.7 m person and 0.30 m cat (silhouettes in two crossed planes), 0.75 m table with a 1.2 x 0.7 m top (filled top + edges + legs), side by side along +X, labelled (POST_PIXEL). Stands on the floor (Z = 0) beside the scan; honours Unit Scale. Vertex samples are cached per mesh, so it follows the scaling smoothly.
- **Viewport (`scene/view.py`):** after Build's scene step every 3D Viewport is centered on the scan mesh (vertex box, distance 1.8 x its size; a camera view switches to perspective). Step 6 is one row: Build + icon toggles Size refs, Auto Level & Center, Work on the Transform (no Scale button; scale with S). "Work on the Transform" (switched on by Build): Pivot Point = 3D Cursor held at the world origin (0.5 s timer), Transform selected + active, TRANSFORM shown, CAMERAS hidden. Off: TRANSFORM hidden, CAMERAS visibility, pivot, cursor, selection and active object as before (scene["ll_prev_*"]).
- **Viewport buttons (`scene/gizmos.py`):** the three step-6 icons also as `GIZMO_GT_button_2d` in the 3D Viewport, continuing Blender's navigation column (zoom / pan / camera / ortho). Position constants measured in Blender 5.2 (slot = nav size x 0.371, first button 0.52 x 1.25 x 2.1 nav sizes under the visible top, x = visible right edge - 0.75 slot; overlapping sidebar / headers are taken off). Toggles use `wm.context_toggle`; lit while on. Shown with gizmos + navigation gizmos on, in an object folder only. If a future Blender moves its column, adjust SLOT_FAC / TOP_FAC.
- **Standing-person icon (`scene/icons.py`):** Blender has no standing-person icon, so the size-reference silhouette is used: a 64 px PNG written to the temp folder at register (pure-Python PNG writer; bpy.data is restricted there) and loaded with `bpy.utils.previews` for the sidebar, and a Python `Gizmo` subclass (`LIVINGLACQUER_GT_person_button`, custom TRIS shapes) for the viewport button. **Do not use `GIZMO_GT_button_2d.shape`**: setting it crashed Blender 5.2.2 in `GPU_batch_wire_from_poly_2d_encoded` (EXCEPTION_ACCESS_VIOLATION while drawing the viewport, 2026-10-25). New gizmo code is tested in a separate `blender --factory-startup --python` window first, never in the user's session.
- **Step status (`project/steps.py`, 0.3.0):** each step is DONE / STALE / TODO / BLOCKED, read from the files and the .blend, never stored as "current step". 1 object folder; 2 >= 3 photos; 3 convert.plan has nothing left; 4 CAM xml + model + texture published (DONE when Build measured these exact files lining up >= 50 % (`Transform["ll_built"]["align"]`); otherwise STALE when the model is older than the xml or new photos came in; TODO: an engine result not published); 5 `last_check` in livinglacquer.json (no errors, newer than the exports); 6 OBJ_<Object> + cameras under Transform (STALE: exports newer than `Transform["ll_built"]`); 7 every camera has its background file (STALE: calibration fingerprint changed); 8 published, all image paths relative, .blend saved. 6-8 are BLOCKED while their requirement is not done even if old files exist. Cached; refreshed after a file loads / saves, after every job (`jobs.ON_FINISH`), and with the refresh button. The panel greys + folds done steps and opens the current one; each step's main button is big (`project/ui.big_row`) and named after the step.
- **Re-alignment (`build.frame_signature`):** Build stores a hash of the first cameras' poses on `Transform["ll_frame"]`; a different one (Agisoft re-aligned, other engine) resets the Transform and levels it again, because the old rotation / scale belong to another coordinate frame.
- **Agisoft guide window (`engines/guide.py`):** text block "LivingLacquer Agisoft Guide" shown in Blender's small temporary window (`screen.userpref_show`, its area switched to a Text Editor), copy buttons at the top of its sidebar ("Text" tab); Blender's TEXT_PT_find / TEXT_PT_properties get a poll that hides them in that window only (restored on unregister); paths are left out of the text unless "Show paths" is on. Opened by the guide button and by Open Metashape.
- **5 steps (0.3.2):** the panel shows 1 Object, 2 Photos (receive + convert & sort), 3 Reconstruct (engine + Check Links), 4 Build Scene & Cameras (build, undistort + camera photos, look-through ◀ ▶, photo opacity / front-back live), 5 Package. `steps.compute_stages` still computes the plan's 8 stages (code comments and the plan keep those numbers); `steps.compute` folds them (`STAGES`): a step is done when all its stages are, else it shows its first open stage. Green swatch = done, red swatch + red header (alert) = a problem (STALE, or Check Links errors), ▶ = current. The Metashape sidebar panel is gone (its importer stays in File › Import; its tools are in step 4).
- **Camera photos and "Work on the Transform":** Blender draws no background photo for a hidden camera, and the toggle hides CAMERAS. Look Through / ◀ ▶ switch the toggle off first (`metashape/operators._show_cameras`). Confirmed with screenshots in a separate Blender (photo visible -> hidden with the toggle -> back after ▶).
- **Context-aware Agisoft guide (0.3.3):** `agisoft.project_state` reads Metashape's own files without Metashape: `.psx` exists, `.files/lock` (open), `.files/0/0/frame.zip` doc.xml (`<photo path=...>` relative to that folder: count, how many do not resolve and where Metashape looks; `<model` = model built), `.files/0/chunk.zip` doc.xml (`<transform>` count = aligned cameras); parsed once per zip mtime. `guide_status` marks each guide line done from that plus the exports; the guide lists only what is left (Change Path first when photos moved), or "Nothing left to do in Agisoft" + the next step in Blender. Rewritten every 3 s while the window is open; "Show all steps" lists the done ones as [done].
- **0.3.5:** Check Links counts as stale only after new exports (saving the .blend no longer turns step 3 red). The ↻ next to Undistort is a one-shot "Redo All" with a confirm (`pipe_undistort(redo_all=True)`); the sticky `pipe_overwrite` switch is gone (it made every Build redo all 52 photos). Build switches "Work on the Transform" on only on the first (levelling) Build; later Builds end looking through the first camera with its photo (`scene/operators.show_first_camera`).
- **Replaced photos (0.3.6):** cameras are matched to photos by name (label = file stem; the XML holds no paths). Undistort records each source photo's [size, mtime] in livinglacquer.json `photo_signatures` (merged; first run after 0.3.6 takes the current photos as the baseline). A different size or a date more than 2 s off (`scene.build.photo_changed`) makes Undistort redo that camera photo, step 4 red ("N photo(s) replaced") and Check Links C14 list it. Not covered: COLMAP results (their camera photos come from the engine).
- **Receiver vs browsers (0.3.7, first real iPhone test):** Brave (and Chrome's HTTPS-First) turn the QR's `http://` into `https://` and fail with ERR_SSL_PROTOCOL_ERROR. The receiver peeks at the first byte (0x16 = TLS handshake), counts it, closes at once (lets some browsers fall back to http) and step 2 shows a red hint: open in Safari, or Brave Shields › Upgrade to HTTPS off. Also: http.server's SO_REUSEADDR let a second Blender bind the same port on Windows; `_Server` now asks for SO_EXCLUSIVEADDRUSE so start() moves on to the next free port.
- **Responsiveness (0.3.8, first real Open Source run, 45 iPhone photos):** COLMAP / OpenMVS at normal priority with all cores starved Blender's UI ("Keine Rückmeldung") although the job kept running. All job subprocesses now start with BELOW_NORMAL_PRIORITY_CLASS (`jobs.BACKGROUND_FLAGS`) and OpenMVS gets `--max-threads` = cores - 2. TextureMesh crashed (0xC0000005) in local seam levelling on the Teacup; the Texture step accepts that exit code and a conditional step (`jobs.Step(when=...)`) re-runs it with `--global-seam-leveling 0 --local-seam-leveling 0` when no scene_texture.obj came out. New Object refuses an object folder as parent (the Teacup had been created inside the Teapot's folder), and the remembered objects folder steps up one level when it points at an object folder.
- **Guide window for real Metashape use (0.3.9-0.4.0):** exports of another engine published earlier (same file names) only count as Agisoft exports when written after that publish; `published_undistorted` only holds while the XML is still the engine's own. File steps have two copy buttons, Folder (address bar) and Name (File name box) - Metashape's Qt dialogs did not take a pasted full path (`pipe_copy_path(part=FOLDER|NAME)`). The guide window is kept above other programs on Windows (`guide.set_topmost`: EnumWindows for this process's "Text Editor" window + SetWindowPos HWND_TOPMOST; argtypes must be declared or the 64-bit HWND is cut and Windows answers error 1400), retried for 5 s after opening; "Keep on top" switch.
- **Masks (0.4.1, `ingest/masks.py`, `ingest/mask_worker.py`):** step 2 "Make Masks" writes `zz.Scan\zz.Masks\<photo stem>_mask.png` (same size as the stored photo pixels, EXIF rotation not applied - Metashape / COLMAP read stored pixels; white = subject, black = ignored). AI = U^2-Net (rembg's u2net.onnx, 175,997,641 bytes, downloaded once into `<Blender user>\datafiles\livinglacquer\models`) run with onnxruntime installed `--no-deps` (its own numpy would shadow Blender's); COLOR = distance from the median border colour. Clean-up: keep the shape nearest the centre (Pillow flood fill - note `Image.fromarray` images are read-only, `.copy()` them), fill holes, grow the edge (`pipe_mask_grow`, ⚙). Teacup: 45 masks in 52 s, only the cup kept in all views. "Check Masks" writes `zz.check_masks.jpg` (masked part red) and shows it in a small Image Editor window. Agisoft guide: "1b. Import Masks" (From File, template `<zz.Masks>\{filename}_mask.png`, one copy button) and "Apply masks to: Key points" on Align, only when masks exist; done when the project's frame doc mentions masks. Open Source: opt-in ("Use masks", `pipe_colmap_masks`): masks copied to `<work>\masks\<lens group>\<photo>.png` + `--ImageReader.mask_path`. On the Teacup it aligned 13 of 45 (only the top-down set; 1-2.5k SIFT points per photo on the glossy cup) vs 33 without masks.
- **Stale depth maps (0.4.2):** OpenMVS DensifyPointCloud reuses `depthNNNN.dmap` in the work folder by image index; leftovers from a run with another camera set crash it (0xC0000005). Open Source `prepare` now deletes `depth*.dmap` and `scene*` like Hybrid's.
- **Open Source alignment + masks for the mesh (0.4.3):** COLMAP runs with 16384 features, peak threshold 0.003, guided matching and looser mapper thresholds (init inliers 50, abs pose 15 / 0.15, min matches 10): the Teacup upright set went from 13 to 30 of 30 photos (defaults kept only the top-down shots; the side views of a plain lid with a blurred background had ~3000 features). Masks no longer go to COLMAP; with "Use masks" they are written as images named like the photos (`work/masks`), undistorted by a second `image_undistorter` run with the same model (`work/dense_masks`), thresholded to `<stem>.mask.png` (`work/mvs_masks`) and passed to DensifyPointCloud `--mask-path --ignore-mask-label 0`. TextureMesh reads `scene.mvs` (no masks: with the dense scene it paints masked pixels black) and runs without seam levelling: with it, TextureMesh 2.4 painted black blobs (13 % of the atlas) or crashed. Tested headless on a scratch Teacup copy: 30 cameras, cup only, clean texture, 5 min.
